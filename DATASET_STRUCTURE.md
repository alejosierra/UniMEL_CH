# Dataset structure expected by the UniMEL pipeline

This repository expects a set of JSON files and image folders for the Wikidiverse pipeline. The code in [code/untils/dataset.py](code/untils/dataset.py) and [code/main.py](code/main.py) reads these files in several stages.

## 1. Entity input files

Used by the entity summarization step.

### Paths
- `ent.train_data_dir`
- `ent.val_data_dir`
- `ent.test_data_dir`

### Expected file type
- JSON

### Expected structure
The file is expected to be a flat JSON object mapping entity IDs to descriptions:

```json
{
  "Q1": "Albert Einstein was a physicist known for the theory of relativity.",
  "Q2": "Paris is the capital city of France."
}
```

### What the code expects
- Keys are treated as entity IDs.
- Values are treated as entity descriptions.

### Output produced by the code
The script writes a JSON array of objects like:

```json
[
  {
    "ids": "Q1",
    "des": "Albert Einstein was a physicist known for the theory of relativity.",
    "sum": "Generated summary"
  }
]
```

---

## 2. Mention input files

Used for mention-based augmentation.

### Paths
- `mention.train_mentions_dir`
- `mention.val_mentions_dir`
- `mention.test_mentions_dir`

### Expected file type
- JSON

### Expected structure
The file should be a JSON array of mention objects:

```json
[
  {
    "ids": "M1",
    "name": "Einstein",
    "category": "Person",
    "context": "Albert Einstein was a physicist.",
    "cands": ["Q1", "Q2", "Q3"]
  }
]
```

### Required fields
- `ids`: mention identifier
- `name`: mention surface form
- `category`: entity category such as Person, Organization, Location
- `context`: surrounding context text
- `cands`: candidate entity IDs

### Output produced by the code
The script may add:
- `des_llava`: generated image-based description
- `des`: generated text-based description
- `score`: similarity scores
- `new_cands`: reduced candidate list after top-k selection

---

## 3. Mention image folders

Used for image-based mention description generation.

### Paths
- `mention.train_kb_img_folder`
- `mention.val_kb_img_folder`
- `mention.test_kb_img_folder`

### Expected file type
- Folder containing image files

### Expected structure
The folder should contain one image per mention, aligned by index.

Example:

```text
train_image/
  train_0.jpg
  train_1.jpg
  train_2.jpg
```

The code looks for images using the index of the mention entry:

```python
image_dir = image_dir + str(i) + ".jpg"
```

So the image file list must be aligned with the mention array order.

---

## 4. Mention files after image description generation

Used by the text-based mention augmentation stage.

### Paths
- `mention.train_data_dir`
- `mention.val_data_dir`
- `mention.test_data_dir`

### Expected file type
- JSON

### Expected structure
This should be the same mention JSON array, but with a `des_llava` field added:

```json
[
  {
    "ids": "M1",
    "name": "Einstein",
    "category": "Person",
    "context": "Albert Einstein was a physicist.",
    "cands": ["Q1", "Q2", "Q3"],
    "des_llava": "Generated description from the image"
  }
]
```

### Output produced by the code
The script adds a `des` field generated by the text model.

---

## 5. Entity embedding input files

Used to generate entity embeddings.

### Paths
- `embed.train_data_dir`
- `embed.val_data_dir`
- `embed.test_data_dir`

### Expected file type
- JSON

### Expected structure
This file should be a JSON array of entity objects with `ids`, `name`, and `sum`:

```json
[
  {
    "ids": "Q1",
    "name": "Albert Einstein",
    "sum": "Physicist known for relativity"
  }
]
```

### What the code does
It combines `name` and `sum` into one text string and computes an embedding for it.

---

## 6. Entity embedding output files

Used for top-k retrieval.

### Paths
- `embed.train_embed_dir`
- `embed.val_embed_dir`
- `embed.test_embed_dir`

### Expected file type
- JSON

### Expected structure
The output is a JSON array of embedding objects:

```json
[
  {
    "ids": "Q1",
    "emb": [0.12, 0.45, 0.78, 1.23]
  }
]
```

---

## 7. Top-k retrieval inputs

Used to build the candidate shortlist for each mention.

### Paths
- `top.train_database_emb`
- `top.val_database_emb`
- `top.test_database_emb`
- `top.train_database_sum`
- `top.val_database_sum`
- `top.test_database_sum`
- `top.train_mention_dir`
- `top.val_mention_dir`
- `top.test_mention_dir`

### Expected file types
- Embedding file: JSON array of `{ids, emb}`
- Summary file: JSON array of `{ids, name, sum}`
- Mention file: JSON array of mention objects with `name`, `context`, `cands`, `ids`

### Output produced by the code
The script adds:
- `score`: similarity scores for each candidate
- `new_cands`: top-k candidate IDs

---

## 8. Inference input files

Used by the final inference stage.

### Paths
- `infer.train_database_sum`
- `infer.val_database_sum`
- `infer.test_database_sum`
- `infer.train_mention_topK_dir`
- `infer.val_mention_topK_dir`
- `infer.test_mention_topK_dir`

### Expected file types
- Entity summary file: JSON array of `{ids, name, sum}`
- Mention top-k file: JSON array of mention objects with `new_cands` and description fields

---

## Notes on the current configuration

In your current [config/wikidiverse.yaml](config/wikidiverse.yaml), the main input files are:

- [config/wikidiverse.yaml](config/wikidiverse.yaml) → `ent.train_data_dir` expects a JSON object mapping entity IDs to descriptions.
- [config/wikidiverse.yaml](config/wikidiverse.yaml) → `mention.train_mentions_dir` expects a JSON array of mentions with `cands` and context.
- [config/wikidiverse.yaml](config/wikidiverse.yaml) → the image folders must contain one image per mention in the matching index order.

This matches the implementation in [code/untils/dataset.py](code/untils/dataset.py).
